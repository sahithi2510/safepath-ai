1. ABSTRACT & EXECUTIVE SUMMARY
================================================================================

Commercial navigation systems (such as Google Maps, Apple Maps, and OpenStreetMap
routers) calculate travel paths based on minimizing metric distance or transit time.
For vulnerable pedestrians—specifically women traveling alone, elderly citizens,
and night commuters—these algorithms routinely suggest isolated alleys, unlit
pathways, and high-crime corridors merely because they represent the shortest
geometric distance.

SafePath AI is an intelligent, context-aware pedestrian navigation system that
calculates walking routes by dynamically balancing transit time, physical distance,
and relative street-level risk. The core routing engine is powered by a multi-
objective variant of the A* search algorithm, driven by a dimensionless, normalized
multi-criteria cost function:

    cost = alpha * normalized_time + beta * normalized_distance + gamma * normalized_risk
    where alpha + beta + gamma = 1.0 (with non-negative weights).

Street-level risk values are generated via an offline-trained XGBoost classification
model supported by a 15-feature spatio-temporal pipeline, integrating metric Kernel
Density Estimation (KDE) over historical crime incident coordinates, ambient street
lighting proxies, safe zone proximity (police stations, hospitals, pharmacies, transit
stations), temporal cyclic encodings, and real-time weather observations. Model
inferences are accompanied by TreeSHAP (SHapley Additive exPlanations) to provide
transparent, additive feature attributions for route risk scores.

The platform is engineered across a multi-tier production architecture:
1. A Spring Boot 3.3 / Java 21 monolith managing authentication (BCrypt, JWT), spatial
   pathfinding, rate limiting, and business logic.
2. A PostgreSQL 15 / PostGIS spatial database with 17 versioned Flyway migrations.
3. A FastAPI / Python 3.11 microservice providing bounded batch ML scoring (<= 500
   segments) and SHAP explainability.
4. A React Native / Expo mobile application utilizing an interactive OpenStreetMap /
   Leaflet visualization engine without commercial API key watermarks or restrictions.

The codebase is validated by 223 automated tests (160 Spring Boot JUnit tests, 63
Python pytest tests, and zero-error TypeScript validation). The platform demonstrates
measurable trade-offs across 3 route modes: FASTEST minimizes transit time, SAFEST
minimizes cumulative street risk, and BALANCED achieves an optimal compromise.

2. INTRODUCTION & PROBLEM FORMULATION
================================================================================

2.1 Background & Motivation
Urban pedestrian navigation is an essential daily utility. However, urban
environments are heterogeneous: two parallel streets of identical length may present
radically different safety profiles due to disparities in street lighting, ambient
foot traffic, proximity to emergency infrastructure, and historical crime occurrences.

According to urban safety studies, fear of crime alters pedestrian mobility patterns,
disproportionately affecting women, university students, and shift workers. When forced
to walk after dusk, pedestrians frequently face an impossible dilemma: choose the route
suggested by conventional GPS applications (often dark and secluded) or guess an
alternative route without objective information.

2.2 Limitations of Commercial Mapping Systems
Contemporary mapping applications suffer from critical architectural and algorithmic
limitations regarding personal pedestrian safety:
1. Unidimensional Optimization: Systems like Google Maps and OSRM optimize solely for
   distance, road hierarchy, or vehicular transit speed.
2. Absence of Safety Context: Commercial routing algorithms do not incorporate crime
   density, street lighting infrastructure, or proximity to emergency facilities into
   their path cost calculations.
3. Black-Box Routing: Existing safety apps provide arbitrary safety ratings without
   algorithmic justification, lacking explainable machine learning outputs.
4. Data Fabrication & Privacy Risks: Commercial crowdsourced apps often suffer from
   data poisoning, unmoderated false alarms, and leakage of reporter identities.

2.3 Problem Statement & Research Questions
The core research problem addressed by SafePath AI is:
"How can an automated routing engine find pedestrian paths across complex urban road
networks that mathematically minimize exposure to street-level safety risks without
imposing disproportionate or impractical travel time detours, while preserving
transparency, data integrity, and strict algorithmic optimality?"

Core Research Questions:
- RQ1: How can heterogeneous metrics (seconds, meters, and statistical risk
  probabilities) be mathematically combined into a dimensionless objective function
  without inducing heuristic distortion?
- RQ2: How can spatial-temporal machine learning models estimate street-level risk
  from historical incident data without spatial leakage across coarse administrative
  boundaries?
- RQ3: Can TreeSHAP explainability provide actionable, non-causal safety insights
  to end users in real time?

2.4 Project Objectives & Scope
- Objective 1: Implement a multi-objective A* search engine supporting customizable
  user preference weights (alpha, beta, gamma).
- Objective 2: Build an end-to-end ML training and inference pipeline using Random

- Objective 3: Implement TreeSHAP explainability to explain why a specific street

  bounding-box queries, Haversine proximity calculations, and spatial indices.
- Objective 5: Deliver an interactive cross-platform mobile application with zero

3. LITERATURE REVIEW & GAP ANALYSIS
================================================================================

3.1 State of the Art in Safe Navigation
Early approaches to safe routing modeled crime as static polygons to be avoided via
computational geometry. However, polygon-avoidance algorithms frequently fail in dense
urban grids where avoiding an entire neighborhood produces disconnected graphs or
absurdly long detours.

Recent literature frames safe routing as a Multi-Constrained Shortest Path (MCSP) or
Multi-Objective Shortest Path (MOSP) problem. While MOSP is NP-hard in the general case
with non-linear Pareto frontiers, linear scalarization using non-negative weight
combinations allows optimal path discovery via generalized A* or Dijkstra search in
polynomial time O(|E| + |V| log |V|).

3.2 Spatio-Temporal Crime Modeling
Criminological theory (Routine Activity Theory and Crime Pattern Theory) demonstrates
that crime is not uniformly distributed across space; it clusters at "crime generators"
and "crime attractors" with pronounced temporal periodicity (peaking at night and on
weekends).

Previous systems frequently committed spatial ecological fallacy by assigning
district-level aggregate crime totals directly to individual road segments. SafePath AI
solves this by employing Kernel Density Estimation (KDE) using a planar metric coordinate
reference system (EPSG:3857) with Gaussian kernels, strictly bounded by spatial
bandwidth parameters (h = 500m and h = 1000m).

3.3 Explainable Artificial Intelligence (XAI) in Public Safety
While deep neural networks and gradient-boosted decision trees deliver high
classification accuracy in tabular spatial tasks, their adoption in safety-critical
systems is constrained by "black-box" opacity.

SafePath AI integrates TreeSHAP (Lundberg & Lee, 2017), which leverages cooperative
game theory to calculate Shapley values across tree ensembles. TreeSHAP provides two
unique mathematical guarantees essential for scientific validity:
1. Local Accuracy (Additivity): sum(phi_i) = f(x) - E[f(x)]
2. Consistency: If a model changes so that the marginal contribution of feature i
   increases, its Shapley value cannot decrease.

6.1 Multi-Objective Risk-Aware A* Routing Algorithm

6.1.1 Mathematical Cost Function:
    C(e) = alpha * T_norm(e) + beta * D_norm(e) + gamma * R_norm(e)
    where alpha + beta + gamma = 1.0 (with alpha >= 0, beta >= 0, gamma >= 0).

6.1.2 Dimensionless Normalization Formulation:
    T_norm(e) = walk_time_seconds(e) / 3600.0   (Duration expressed in hours)
    D_norm(e) = length_meters(e) / 10000.0      (Distance expressed in 10-km units)
    R_norm(e) = risk_score(e) in [0.0, 1.0]     (Segment relative risk score)

6.1.3 Route Profiles & Weight Configurations:
+-----------------+--------------+------------------+---------------+-------------------------------+
| Profile Name    | Time (alpha) | Distance (beta)  | Risk (gamma)  | Behavioral Characteristics    |
+-----------------+--------------+------------------+---------------+-------------------------------+
| FASTEST         | 0.80         | 0.20             | 0.00          | Pure speed; ignores risk      |
| BALANCED        | 0.30         | 0.20             | 0.50          | Optimal compromise            |
| SAFEST          | 0.10         | 0.10             | 0.80          | Maximum risk minimization     |
| SOLO_TRAVELLER  | 0.15         | 0.15             | 0.70          | Elevated safety for solos     |
| TOURIST         | 0.30         | 0.30             | 0.40          | Major lighted streets         |
| ELDERLY         | 0.10         | 0.40             | 0.50          | Minimizes physical distance   |
| STANDARD        | 0.30         | 0.20             | 0.50          | Default baseline (= BALANCED) |
+-----------------+--------------+------------------+---------------+-------------------------------+

6.1.4 Formal Proof of Heuristic Admissibility (h = 0):
For A* search to guarantee optimal path discovery, the heuristic h(n) must be admissible:
    h(n) <= h*(n) for all nodes n.
Because the remaining edge cost h*(n) combines heterogeneous time, distance, and
uncalibrated risk metrics, Euclidean distance cannot guarantee underestimation of
the total multi-objective cost.
Setting h(n) = 0.0 guarantees that 0.0 <= h*(n) for all non-negative edge costs C(e) >= 0.
Under h(n) = 0.0, A* reduces to Dijkstra's algorithm, mathematically guaranteeing
the discovery of the globally optimal multi-criteria path without heuristic distortion.

6.1.5 Deterministic 3-Tier Tie-Breaking:
Priority queue tie-breaking comparator:
    1. Compare total multi-criteria fScore.
    2. If equal, compare accumulated gScore (preferring deeper progress).
    3. If equal, break ties deterministically by unique Node ID.

6.2 Machine Learning Spatial-Temporal Risk Model

6.2.1 15-Feature Vector:
    1. crime_density_500m        (Metric KDE bandwidth 500m, EPSG:3857)
    2. crime_density_1km         (Metric KDE bandwidth 1000m, EPSG:3857)
    3. severity_weighted_density (KDE weighted by crime severity index 1-5)
    4. recent_crime_density      (KDE restricted to past 90 days)
    5. night_crime_density       (KDE restricted to 20:00 - 05:00)
    6. hour_of_day               (Integer 0 - 23)
    7. day_of_week               (Integer 0 - 6, 0 = Monday)
    8. lighting_score            (Float 0.0 - 1.0; lit=yes: 1.0, lit=no: 0.1, missing: 0.5)
    9. activity_proxy            (Float 0.0 - 1.0; commercial/transit corridor proxy)
    10. nearest_police_m         (Haversine distance to nearest police station)
    11. nearest_hospital_m       (Haversine distance to nearest hospital)
    12. nearest_transport_m      (Haversine distance to nearest metro/bus station)
    13. weather_precipitation    (Precipitation rate in mm/h)
    14. weather_visibility       (Horizontal visibility in meters)
    15. verified_report_count    (Count of verified citizen hazard reports)

6.2.2 Metric Kernel Density Estimation (KDE):
All coordinates are projected onto Spherical Mercator (EPSG:3857) where distances are
in metric meters. Gaussian density is calculated as:
    f_h(x) = (1 / (n * 2 * pi * h^2)) * sum( w_i * exp(-||x - x_i||^2 / (2 * h^2)) )

6.2.3 TreeSHAP Additive Explainability:
Every scored segment produces Shapley values phi_i satisfying exact additive reconstruction:
    f(x) = E[f(X)] + sum(phi_i)  (verified to 10^-4 numerical accuracy).

9. ARCHITECTURAL DISTINCTIONS: FACTS, ASSUMPTIONS, CHOICES, LIMITATIONS
================================================================================

9.1 Facts (Empirically Supported):
1. A* with zero heuristic (h = 0) is mathematically guaranteed to find the optimal path.
2. Training on district-level crime data without coordinates introduces ecological fallacy.
3. TreeSHAP guarantees exact additive feature attribution reconstruction within 10^-4.
4. BCrypt with work factor 12 provides computational resistance against rainbow tables.

9.2 Assumptions (Explicitly Documented):
1. OSM road network geometries accurately represent walkable pedestrian access.
2. Road segments within 100m of commercial corridors have higher nighttime foot traffic.
3. User route preference profiles represent reasonable weight distributions for user groups.

9.3 Implementation Choices (Engineering Decisions):
1. Spring Boot Monolith chosen over microservices to eliminate distributed transaction overhead.
2. In-Memory Sliding-Window Rate Limiter chosen over Redis to minimize external dependencies.
3. Leaflet WebView chosen over Google Maps SDK to eliminate commercial billing dependencies.
4. Telephony URI Fallbacks (tel:112) ensure emergency calling works even during network outages.

9.4 Limitations & Future Roadmap:
1. Spatial Coverage: Ground-truth crime data seeded for central Bangalore evaluation corridor.
2. Crime Reporting Bias: Police records reflect reported crimes rather than total occurrences.
3. Smart Streetlight IoT: Future work can integrate municipal IoT street lighting feeds.
